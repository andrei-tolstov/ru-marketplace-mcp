# Lessons Learned

## Timing and Concurrency Tests on Loaded CI Runners (Windows)

- **Pattern**:
  Использование реальных настенных часов (`time.monotonic()`) с короткими задержками `asyncio.sleep(0.05..0.08)` в асинхронных тестах таймаутов и конкурентности приводит к флакам на Windows CI раннерах. Квант системного таймера на Windows составляет ~15.6 мс, а на виртуальных раннерах GitHub Actions накладные расходы планировщика могут вызывать задержки свыше 25-50 мс. В результате `asyncio.wait_for` может сработать раньше, чем завершится вспомогательная функция со сном.

- **Rule to prevent recurrence**:
  1. Для проверки бюджетов времени и таймаутов **никогда не использовать реальный `asyncio.sleep`**. Вместо этого мокать `time.monotonic` через `monkeypatch` виртуальными часами (`current_time = [1000.0]`) и явно продвигать время в моках источников.
  2. Для проверки конкурентного выполнения корутин в `asyncio.gather` использовать взаимную синхронизацию через `asyncio.Event` (каждая корутина сигнализирует о своём старте и ждёт старта другой) — это гарантирует одновременное выполнение без задержек и флаков.
  3. Для проверки последовательного выполнения корутин использовать счётчик активных задач (`assert active_concurrency == 1`).
